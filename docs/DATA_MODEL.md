# Data model

SQLite, one file (`jobowl.db`), WAL mode, foreign keys on. Schema defined in Drizzle (`src/main/db/schema.ts`); migrations generated by drizzle-kit and applied at startup before any window opens. A backup is taken before each migration.

Conventions:

- IDs are ULIDs stored as `TEXT` (sortable by creation time, safe to show).
- Timestamps are ISO 8601 UTC `TEXT`. Dates without time (date applied, employment dates) are `YYYY-MM` or `YYYY-MM-DD` strings.
- JSON columns are `TEXT` holding JSON validated by a Zod schema in `src/shared/schemas/` on every read and write.
- Nothing is hard-deleted except on explicit user request. Jobs and matches are archived.

## The profile

The profile is the most important structure in the app: it's the only source of facts for anything JobOwl writes. It's stored whole, as a versioned JSON document, because it's always read and written as a unit and versions must be immutable.

```ts
// src/shared/schemas/profile.ts (shape; Zod is the real definition)
type Profile = {
  schemaVersion: 1;
  person: {
    fullName: string;
    headline?: string;               // the user's own one-liner, used as-is or not at all
    email: string;
    phone?: string;
    location?: string;               // "Quezon City, PH"
    links: { label: string; url: string }[];   // GitHub, portfolio, LinkedIn
  };
  summary?: ProfileText;             // user-written summary; the AI may shorten it, not extend it
  experiences: Experience[];
  projects: Project[];
  education: Education[];
  certifications: Certification[];
  skills: Skill[];
  languages: { name: string; level?: string }[];
  standardAnswers: StandardAnswer[]; // for application forms
  writingSamples: ProfileText[];     // optional, for voice matching; never quoted as facts
};

type Experience = {
  id: string;                        // stable across versions, so tailored resumes can cite it
  employer: string;
  title: string;
  location?: string;
  employmentType?: 'full-time' | 'part-time' | 'contract' | 'internship' | 'freelance';
  start: string;                     // YYYY-MM
  end: string | 'present';
  bullets: Bullet[];
  skills: string[];                  // skill ids used in this role
};

type Bullet = {
  id: string;
  text: string;                      // the user's wording, verified by the user
  metrics: string[];                 // exact numbers/claims in the bullet ("40%", "12k users"), extracted at save
  tags: string[];                    // optional: "backend", "leadership"
  hidden?: boolean;                  // kept but never used
};

type Project = { id; name; role?; url?; start?; end?; bullets: Bullet[]; skills: string[] };
type Education = { id; school; degree?; field?; start?; end?; honors?: string[] };
type Certification = { id; name; issuer?; date?; url? };
type Skill = { id; name; aliases: string[]; level?: 'familiar' | 'proficient' | 'expert'; years?: number };
type StandardAnswer = { id; key: StandardAnswerKey | 'custom'; question?: string; answer: string };
type ProfileText = { id: string; text: string };
```

`StandardAnswerKey` covers the questions forms ask most: `work_authorization`, `requires_sponsorship`, `notice_period`, `salary_expectation`, `willing_to_relocate`, `earliest_start_date`, `pronouns`, `gender`, `race_ethnicity`, `veteran_status`, `disability_status`, `how_did_you_hear`. EEO keys default to "I don't wish to answer".

Rules:

- Item IDs (`exp_…`, `blt_…`, `skl_…`) are stable across versions. Editing a bullet's text keeps its ID; deleting and re-adding makes a new one.
- `metrics` is extracted deterministically on save (numbers, percentages, currency, counts with units) and shown to the user. The Checker uses it: a number in a tailored line must appear in the cited bullets' `metrics`.
- A profile version is immutable once saved. Saving creates a new version.

## Retention

- Dismissed jobs and their matches are archived after 30 days, deleted after 180.
- Closed jobs with no application are deleted after 90 days.
- Anything linked to an application is kept until the user deletes the application.
- `ai_calls.debug_payload` is pruned after 7 days; the row stays for cost history.
